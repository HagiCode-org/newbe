## 开始了，但是没完全开始

Dapr 是一个可移植的、事件驱动的运行时，它使任何开发人员能够轻松构建出弹性的、无状态和有状态的应用程序，并可运行在云平台或边缘计算中，它同时也支持多种编程语言和开发框架。

截至发文此时，最新的 1.4 版本也已经正在酝酿了。查看 github 上 Are you using Dapr? 的 issue，你可以看到很多已经将该技术用于产线的用例。

![Are you using Dapr](/images/20210913-006.png)

其中也不乏一些中国知名公司的应用，这里有一些简单的列举：

- **Tencent**: Using Dapr for Q&A robot ai in game industry , utilizing its ServiceInvocation and State capabilities.
- **Alibaba Cloud**: Using Dapr to invoke the baas on the Function Compute of Alibaba Cloud
- **DingTalk**: Dapr provides multi-language support and portability for dingtalk to deploy on cloud and on-premises
- **AutoNavi**: Using Dapr sidecar in Faas runtime to support existing service invocation, state management, etc.
- **RED(XiaoHongShu E-commerce)**: 1. Using Dapr to extend RED's own faas platform's function ability 2. Interested in combining it with Envoy
- 列表未尽，可以转到 https://github.com/dapr/dapr/issues/3169 进行查看

我们完全可以认为，这一切已经都开始了。

但是，还是有很多伙伴仍然不理解:

- 究竟什么是 dapr？
- 解决什么问题？
- 迁移成本如何？
- 一定要 k8s 吗？
- state store 能不能当做缓存使用？

对于这些老伙计来说，这一切可以说还没有开始。
